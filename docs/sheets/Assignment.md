# Student Activity — Requirement & Implementation Specification

> **Scope:** Student activities delivered through the Kutties app.
> **Activity types:** Assignment · Task · Notification
> The active `assignmentTypeRef` column in `reftbl` drives the type dropdown.
> **Status:** ✅ Fully implemented.

---

## 1. Shared concepts (all types)

| Concept | Details |
|---|---|
| **Activity type** | `Assignment` \| `Task` \| `Notification` — sourced from `reftbl.assignmentTypeRef` |
| **Category** | Free pick from `reftbl.assignmentCatRef` (e.g. "Homework", "Project") |
| **Assignor/creator** | Teacher / staff who creates the activity |
| **Assignee** | Student the activity is targeted at |
| **Course** | The course this activity belongs to — derived from the student's enrolled courses; no separate input required |
| **Start date** | When the activity becomes active |
| **End date** | Deadline / due date |
| **Description** | Rich text body of the activity |
| **Overdue flag** | Computed: `today > endDate AND status ≠ 'closed'` |

## 2. Activity types

### 2.1 Assignment

An assignment requires a **submission artefact** (document or photo) and carries a **rating**.

#### 2.1.1 Roles

| Role | Who | Permissions |
|---|---|---|
| **Assignor / Creator** | Teacher who creates it | Create · Edit (own) · **Assign Reviewer** · Close · View |
| **Assignee** | Target student | Submit response · View own |
| **Reviewer** | Teacher designated by the Assignor | Review · Rate · Close |

> **Reviewer assignment rule:** The Assignor sets the `Reviewer` field when creating or editing the activity (modes `add` / `edit`). A Reviewer is **required** for Assignment and Task — it can be the Assignor themselves or any other staff member. It is not applicable for Notification.

#### 2.1.2 Status lifecycle

```
open → in-progress → in-review → closed
```

| Transition | Who can trigger | Rule |
|---|---|---|
| `open → in-progress` | Assignee | On first submission upload |
| `in-progress → in-review` | Assignee | When submission is finalised |
| `in-review → closed` | Reviewer **or** Assignor | Rating required unless overdue |
| Any → `closed` (overdue) | Reviewer **or** Assignor | Negative rating auto-applied; rating locked |

#### 2.1.3 Submission artefact (response)

- Either a **document** (PDF / Word / etc.) or an **image** (camera or gallery) is **mandatory**.
- Stored via `ExcelApi.uploadAttachment()` → URL saved in `SubmissionAttachments`.
- Assignee may replace the file while status is `in-progress`.

#### 2.1.4 Rating rules

| Condition | Rule |
|---|---|
| Closed, not overdue | Reviewer / Assignor **must** provide a rating (1 – 5 stars) before closing |
| Closed, overdue | Negative rating applied automatically (`-1` sentinel); **no one** can change it after close |
| Not yet closed | Rating field is hidden / disabled |

---

### 2.2 Task

A task is a lighter activity — **no artefact is required, no rating is given**.

| Aspect | Value |
|---|---|
| Artefact | Not required |
| Rating | Not applicable |
| Status lifecycle | Same as Assignment: `open → in-progress → in-review → closed` |
| Roles | Same as Assignment (Assignor, Assignee, Reviewer) |
| Overdue | Same rule as Assignment |

---

### 2.3 Notification

A notification is a one-way communication with minimal workflow.

| Field | Required | Notes |
|---|---|---|
| Assignor | ✅ | Sender |
| Assignee | ✅ | Target student |
| Category | ✅ | From `reftbl.assignmentCatRef` |
| Description | ✅ | Message body |
| Status | — | `open` or `closed` only |
| Artefact | ✗ | None |
| Rating | ✗ | None |
| Reviewer | ✗ | None — hidden in form and detail screen |
| Overdue | ✗ | None |

**Close rule:** Only the **assignee** can close a notification (acknowledges it).

## 5. Domain model (`StudentActivityModel`)

**File:** [`src/db/models/studentactivity.model.ts`](../../src/db/models/studentactivity.model.ts)

```ts
export type ActivityType   = 'Assignment' | 'Task' | 'Notification';
export type ActivityStatus = 'open' | 'in-progress' | 'in-review' | 'closed';

export interface StudentActivityModel extends AuditFields {
  id: string;
  activityType?: ActivityType;     // Excel: ActivityType
  category?: string;               // Excel: Category
  course?: string;                 // Excel: Course
  assignor?: string;               // Excel: Assignor   — staff email (creator)
  assignee?: string;               // Excel: Assignee   — student reg number
  reviewer?: string;               // Excel: Reviewer   — staff email (Assignment / Task)
  title?: string;                  // Excel: Title
  description?: string;            // Excel: Description
  startDate?: string;              // Excel: StartDate  — dd/MMM/yyyy
  endDate?: string;                // Excel: EndDate    — dd/MMM/yyyy
  status?: ActivityStatus;         // Excel: Status
  isOverdue?: boolean;             // Excel: IsOverdue  — computed; stored on close
  submissionAttachments?: string[];// Excel: SubmissionAttachments — pipe-separated → array
  submissionNote?: string;         // Excel: SubmissionNote
  rating?: number;                 // Excel: Rating     — 1–5, or -1 overdue sentinel
  ratingNote?: string;             // Excel: RatingNote — reviewer's note on rating
  closedBy?: string;               // Excel: ClosedBy
  closedAt?: string;               // Excel: ClosedAt   — ISO timestamp
  revision?: number;               // Excel: Revision
}
```

> **Note:** `status` is typed as optional (`?`) in the model (aligns with partial loads), unlike the earlier spec draft.

### Helpers

```ts
/** Computed overdue check — false if already closed or no endDate. */
export function isActivityOverdue(activity: StudentActivityModel): boolean {
  if (!activity.endDate || activity.status === 'closed') return false;
  return new Date() > new Date(activity.endDate);
}

/** Parse pipe-separated attachment URL string → string[]. */
export function parseAttachments(raw?: unknown): string[]

/** Serialize string[] → pipe-separated string for Excel write. */
export function serializeAttachments(urls?: string[]): string | undefined
```

### Mapper — `toStudentActivityModel`

Handles **both** raw Excel PascalCase keys (`ActivityType`, `StartDate`, …) and local DB camelCase keys (`activityType`, `startDate`, …), normalising dates via `normaliseDate()` and coercing numeric fields.

### 9.3 `StudentActivityList`

**File:** [`src/components/activity/StudentActivityList.tsx`](../../src/components/activity/StudentActivityList.tsx)

#### Grouping hierarchy (`SectionList`)

```
Course  [sticky header — collapsible, shows total count]
  └── Student sub-header  [collapsible, shows item count — hidden when scoped to single student]
        └── StudentActivityRow
```

- **Sections** = one per unique `course` value (sorted alphabetically).
- **Student sub-header** = one per `assignee` within a course; hidden when `prefilledReg` is set.
- Courses start **collapsed**; expanding one course collapses any previously open course (accordion).
- Student sub-headers are individually toggle-able.
- Search query auto-expands all courses and students.
- **When `studentRegNumber` or `course` is pre-filtered** (e.g. navigating from Student Details quick action), all matching courses and student sub-headers are **auto-expanded** on load so rows are immediately visible without requiring a tap.

#### Filtering

The list supports three independent filter dimensions via tappable chips on each row (passed down to `StudentActivityRow`):

| Dimension | State var | Behaviour |
|---|---|---|
| Reviewer | `selectedReviewer` | Filter to rows matching reviewer email; tap same to clear |
| Status | `selectedStatus` | Filter to rows matching status |
| Type | `selectedType` | Filter to rows matching activityType |

Additionally: free-text search across `title`, `assignee`, `course`, `category`, `activityType`, `status`.

#### Props / route params

| Param | Description |
|---|---|
| `studentRegNumber` | Pre-filter to a single student |
| `course` | Pre-filter to a single course |
| `headerTitle` | Override header title (default: `'Activities'`) |
| `currentUserEmail` | (Accepted via params; reserved for future default reviewer filter) |

#### Actions

- **Sync** button (header right) — calls `syncSheet(SHEETS.STUDENT_ACTIVITY)` then reloads.
- **FAB** (`+`) — navigates to `StudentActivityForm` with `mode: 'add'`, passing `prefilledRegNumber` and `prefilledCourse`.

### 9.4 `StudentActivityForm`

**File:** [`src/components/activity/StudentActivityForm.tsx`](../../src/components/activity/StudentActivityForm.tsx)

#### Modes

| Mode | Who | What fields are shown |
|---|---|---|
| `add` | Assignor | All except submission / rating / close fields. `Course` picker populated from selected `Assignee`'s enrolled courses |
| `edit` | Assignor | Same as `add`. `Course` picker re-populated from current `Assignee`'s enrolled courses |
| `submit` | Assignee | Submission attachment (required for Assignment), submission note, status advance button |
| `review` | Reviewer | **5-star tap selector** (required if not overdue); overdue activities show a warning and auto-apply `-1` sentinel |

#### Validation rules

| Rule | Condition |
|---|---|
| Attachment required | `activityType === 'Assignment'` AND mode is `submit` |
| Rating required | mode is `review` AND `isOverdue === false` |
| Rating locked | `isOverdue === true` → rating field disabled, sentinel `-1` written |
| End date ≥ start date | Always |
| Reviewer required | `activityType !== 'Notification'` — set by Assignor in `add` / `edit` mode; self-review allowed |

#### Status options per activity type

| Type | Available statuses (in edit mode) |
|---|---|
| `Assignment` / `Task` | `open` · `in-progress` · `in-review` — `closed` only reachable via Review & Rate action |
| `Notification` | `open` · `closed` |

#### Internal constants

```ts
const ACTIVITY_TYPES: ActivityType[]               = ['Assignment', 'Task', 'Notification'];
const STATUS_OPTIONS: ActivityStatus[]              = ['open', 'in-progress', 'in-review'];
const STATUS_OPTIONS_NOTIFICATION: ActivityStatus[] = ['open', 'closed'];
// RATING_OPTIONS removed — rating input is now a 5-star tap selector (Ionicons)
```

## 11. Overdue logic (app-side)

```
On list load (StudentActivityList.loadItems):
  forEach activity where status ≠ 'closed':
    if today > endDate → mark isOverdue = true (local computed; written to sheet on next status change)
```

The `isActivityOverdue` helper is used directly at load time:
```ts
rows = activityRows.map((r) => ({
  ...r,
  isOverdue: r.status !== 'closed' ? isActivityOverdue(r) : r.isOverdue,
}));
```
